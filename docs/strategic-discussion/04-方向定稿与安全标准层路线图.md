# NexusGenesis 方向定稿：Agent 自治安全标准层

> **决策性质**: 方向定稿（由创始人授权，顶级区块链专家全程把控）
> **决策日期**: 2026-08-06
> **状态**: ✅ 已确定，进入执行
> **前置决策**: 确立 **L1 为生态主线（终极愿景）**，**安全标准层为其信任基础设施**——安全层提供密钥安全、PQC 签名与人类接管，L1 承载 Agent 自治生态（任务、NGEN 价值交换、声誉、跨链）。二者**互补协同**：安全层为 L1 上的每个 Agent 提供信任底座，L1 为安全层提供真实生态场景。当前以安全层为开发切入点（前置信任基础，可独立发布），L1 择机推进。

---

## 一、决策背景与结论

### 1.1 主线关系：L1 是生态主线，安全层是它的信任基础设施

> **重要澄清**：**L1 是项目的生态主线（终极愿景）**——它承载 Agent 自治网络的生态（任务、NGEN 价值交换、声誉、跨链）。安全标准层**不是与 L1 并列的另一条线，而是支撑 L1 生态的信任基础设施**。安全层解决"谁有权、密钥安全、人类接管"，L1 解决"Agent 间如何结算价值并形成生态"。二者**互补协同**：L1 上的每一笔 Agent 交易都由安全层密钥体系签名与授权；安全层的密钥能力在 L1 上获得真实生态场景。当前以安全层为开发切入点，是因为它是 L1 的前置信任基础、且能独立发布创造价值；L1 作为生态主线择机推进。

> 之所以 L1 不"立即"作为开发主线推进，是出于工程与资源现实（下表），而非放弃其生态主线地位：

| 维度 | 现实 | 结论 |
|------|------|------|
| 共识成本 | 自研 BFT + PQC + AINVM 对标有团队的工程 | 单节点 JS 实现无法证明"是条链" |
| 去中心化死结 | 无真实需求→无人跑节点→不像去中心化网络 | 因果循环，技术无法解决需求侧 |
| AINVM | 重编译器/运行时工程，无被验证的真实需求 | 消耗最深、回报最不确定 |
| 竞争 | Solana/Celestia/Olas/Fetch 均为资源战 | 单人无资源，必输 |
| 验证 | 无第三方审计、无社区验证者 | 无法建立信任 |

> **互补关系定位（修正前版"完全独立"表述）**：安全层与 L1 不是两条不相干的线，而是**一条价值链路的两端**：
> - **安全层（信任基础设施）**：私钥自持、PQC 签名、人类接管——回答"Agent 是谁、谁有权、密钥是否安全"
> - **L1（应用与结算载体）**：Agent 间 NGEN 转账、任务结算、声誉记录——回答"Agent 之间如何完成价值交换"
> - **协同点**：L1 上的每一笔 Agent 交易都应由安全层的密钥体系签名与授权；安全层的密钥能力在 L1 上获得真实结算场景。已验证：L1 转账引擎（`agentWalletManager`）配合安全层 Dilithium2 签名可端到端跑通。

### 1.2 为什么"跨链 Agent 框架"也不能直接照搬

框架赛道（AgentKit / Olas / Fetch）护城河是"集成深度+生态规模"，不是协议设计。单人写协议无生态，难以突围。

### 1.3 真正的差异化资产

审计现有代码后发现，代码库中有一个**被市场低估、极少人做好**的稀缺能力：

> **PQC 密钥体系 + Agent 钱包自主迁移 + 人类接管机制**

市面上所有 Agent 框架的密钥模型都是"私钥托管在服务器"或"私钥在内存"。NexusGenesis 实现了：**私钥永远不出浏览器/Agent 本地 + 人类可随时接管 + Dilithium2 抗量子签名**的完整链路。这在 **Agent 自治 + 安全合规** 的交叉点是真正的差异化。

## 二、新定位

> **NexusGenesis = Agent 自治的安全密钥与协调标准层（Security & Coordination Layer for Autonomous Agents）**

- **主叙事**: Agent 私钥安全、自主托管、人类接管合规
- **附加值**: 任务/声誉协调协议（黏性功能，非主打）
- **落地形态**: 可独立发布的 SDK + MCP 插件 + 主流链适配器
- **L1 关系**: **生态主线 + 信任底座**——L1 是生态主线（终极愿景），安全层是其信任基础设施。安全层当前为开发切入点（前置信任基础、可独立发布），L1 择机推进。见 [一、1.1](#11-主线关系l1-是生态主线安全层是它的信任基础设施)

## 五、风险与止损

| 风险 | 概率 | 应对 |
|------|------|------|
| 安全标准层冷启动难 | 中 | 靠 MCP/LangChain 插件接入点切入现有生态 |
| 与现有 Agent 框架重叠 | 中 | 主打"私钥安全+人类接管"差异化，不拼生态 |
| 代码提取引入回归 | 中 | 先写 keys 包独立测试，隔离后再重构 SDK |
| 单点维护 | 高 | 保持模块极简化，减少长期维护面 |

**止损点**: 阶段 A 完成后若 `@nexusgenesis/agent-keys` 无任何外部采用信号，则暂停对安全层的进一步投入（仅维护），将重心转向**让安全层作为 L1 信任底座被生态采用**，或按现实重新评估整体投入节奏——L1 作为生态主线的地位不变。
