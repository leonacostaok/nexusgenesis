## 一、决策背景与结论

### 1.1 为什么放弃独立 L1 主线

| 维度 | 现实 | 结论 |
|------|------|------|
| 共识成本 | 自研 BFT + PQC + AINVM 对标有团队的工程 | 单节点 JS 实现无法证明"是条链" |
| 去中心化死结 | 无真实需求→无人跑节点→不像去中心化网络 | 因果循环，技术无法解决需求侧 |
| AINVM | 重编译器/运行时工程，无被验证的真实需求 | 消耗最深、回报最不确定 |
| 竞争 | Solana/Celestia/Olas/Fetch 均为资源战 | 单人无资源，必输 |
| 验证 | 无第三方审计、无社区验证者 | 无法建立信任 |

### 1.2 为什么"跨链 Agent 框架"也不能直接照搬

框架赛道（AgentKit / Olas / Fetch）护城河是"集成深度+生态规模"，不是协议设计。单人写协议无生态，难以突围。

### 1.3 真正的差异化资产

审计现有代码后发现，代码库中有一个**被市场低估、极少人做好**的稀缺能力：

> **PQC 密钥体系 + Agent 钱包自主迁移 + 人类接管机制**

市面上所有 Agent 框架的密钥模型都是"私钥托管在服务器"或"私钥在内存"。NexusGenesis 实现了：**私钥永远不出浏览器/Agent 本地 + 人类可随时接管 + Dilithium2 抗量子签名**的完整链路。这在 **Agent 自治 + 安全合规** 的交叉点是真正的差异化。

## 二、新定位

> **NexusGenesis = Agent 自治的安全密钥与协调标准层（Security & Coordination Layer for Autonomous Agents）**

- **主叙事**: Agent 私钥安全、自主托管、人类接管合规
- **附加值**: 任务/声誉协调协议（黏性功能，非主打）
- **落地形态**: 可独立发布的 SDK + MCP 插件 + 主流链适配器
- **独立 L1**: 降级为 devnet/演示环境，不再投入运营资源

## 四、路线图（三阶段）

### 阶段 A：安全标准层独立 ✅ 已完成（2026-08-06）

1. **提取 `@nexusgenesis/agent-keys` 包** ✅
   - `packages/agent-keys/` — 纯密钥库（PQC、加密、派生、接管、custody）
   - 仅依赖 `@noble/post-quantum`，零其他依赖

2. **重构 SDK 为框架包** ✅

   - 验收通过：`npm test` **6/6 全绿**

3. **扩展 MCP 为安全工具集** ✅
   - `mcp-server/src/index.js` — 新增安全工具：`generate_agent_keys` / `generate_keypair` / `verify_signature` / `validate_address` / `check_spend` / `takeover_guard`
   - 私钥永不离开调用方进程/浏览器，仅产出公开材料 + 加密 envelope
   - 验收通过：模块加载正常，`@nexusgenesis/agent-sdk` file 依赖已安装

> **阶段 A 交付物**：`@nexusgenesis/agent-keys`（生产级密钥库）+ `@nexusgenesis/agent-sdk`（框架包）+ 完整 MCP 安全工具集，三者相互独立、可独立发布与测试。

### 阶段 B：跨链适配 ✅ 已完成（2026-08-06）

4. **ETH 适配器** ✅ `packages/chain-eth`（`@nexusgenesis/chain-eth`）
