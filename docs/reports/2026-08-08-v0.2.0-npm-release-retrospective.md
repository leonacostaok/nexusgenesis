## 2. Failures found & fixed

The publish flow was triggered multiple times; each failure revealed a distinct root cause.

### 2.1 CI: legacy root test suite timed out

**Symptom:** CI job `test (18.x)` failed; `test (20.x)` / `test (22.x)` cancelled (matrix fail-fast).

**Root cause:** The workflows ran the root `npm test`, which executed the legacy L1 test suite (`node --test test/*.test.js`, 38 files). It never finished within the timeout.

**Fix:** Run only the workspace security-package tests instead.

```yaml
# .github/workflows/ci.yml
- name: Test security packages (workspaces)
  run: npm test -ws --if-present
  timeout-minutes: 10
```

```yaml
# .github/workflows/npm-publish.yml
- name: Run tests
  run: npm test -ws --if-present
  timeout-minutes: 10
```

### 2.2 CI: Node 18 missing `globalThis.crypto`

**Symptom:** After removing the legacy tests, `Test security packages (workspaces)` failed on Node 18.x only (local Node 24 passed).

**Root cause:** `@noble/hashes` (bundled by `@noble/post-quantum`) reads secure randomness from `globalThis.crypto.getRandomValues`, which is only defined globally on Node 19+. On Node 18 it is `undefined`.

**Fix:** Polyfill `globalThis.crypto` from `node:crypto.webcrypto` in `packages/agent-keys/src/pqc.js`. Because every package keys through `generateKeyPair`, one fix covers all packages.

```js
// @noble/hashes (bundled by @noble/post-quantum) reads secure randomness from
// globalThis.crypto.getRandomValues, which is only defined globally on Node 19+.
// Polyfill it on older runtimes (Node 18) so keygen works everywhere.
if (typeof globalThis.crypto === 'undefined' || typeof globalThis.crypto.getRandomValues !== 'function') {
  globalThis.crypto = crypto.webcrypto;
}
```

**Verification:** Simulated the Node 18 state by making `globalThis.crypto` `undefined`; after import, `getRandomValues` was a function and keygen returned a valid key pair.

### 2.3 Publish: `package-lock.json` out of sync

**Symptom:** `npm ci` in CI failed with EUSAGE.

**Root cause:** Versions were bumped to `0.2.0`, but `package-lock.json` still referenced `0.1.x`.

**Fix:** Regenerate the lock file locally (`npm install`), commit the refreshed `package-lock.json`, then re-tag.

### 2.4 Publish: npm provenance validation failed

**Symptom:** `npm publish` (with `--provenance`) returned:

```
422 Unprocessable Entity — Error verifying sigstore provenance bundle:
Failed to validate repository information: package.json: "repository.url" is "",
expected to match "https://github.com/nexus-genesis/nexusgenesis"
```

**Root cause:** Only `mcp-server/package.json` had a `repository` field; the five `packages/*` manifests did not. Sigstore provenance requires `repository.url` to match the GitHub repo.

**Fix:** Add a `repository` block to all five package manifests:

```json
"repository": {
  "type": "git",
  "url": "git+https://github.com/nexus-genesis/nexusgenesis.git",
  "directory": "packages/<name>"
}
```

## 4. Release & tag flow

1. Bump versions + align cross-dependencies; refresh lock file.
2. Commit the version/release changes.
3. Create annotated tag: `git tag -a v0.2.0 -m "..."`.
4. Push `master` and the tag. Tag push triggers `npm-publish.yml`.
5. On failure, fix, commit, then **move the tag** to the new commit and re-push:
   - `git tag -f v0.2.0 -m "..."`
   - `git push origin :refs/tags/v0.2.0` (delete remote tag)
   - `git push origin v0.2.0` (recreate → triggers a new run)

> Note: GitHub connectivity was intermittently flaky during this session; a retry loop (`Test-NetConnection github.com -Port 443`) was used until each push succeeded.

---

## 5. Lessons learned

- **Match the workflow to what actually ships.** Legacy L1 tests no longer belong in the security-layer CI; keep only workspace tests.
- **Provenance is strict.** Any published package needs a valid `repository` field, not just the monorepo root.
- **Bumping versions requires a lock refresh.** Always run `npm install` and commit `package-lock.json` before tagging.
- **Node version coverage matters.** Test across the full supported matrix; Node 18 lacks global WebCrypto that newer versions have.
- **Re-triggering a tag run requires moving the tag.** Re-pushing the same tag does not fire a new Actions run; delete + recreate does.
