# NexusGenesis 钱包与跨链方案（白皮书对齐版）

## 核心原则对齐

### 白皮书怎么说
> "Agent 不拥有银行账户，而是直接拥有能量（NGEN）"
> "私钥由 AGENT 自持（主网阶段）"
> "信任不依赖法律合同，而是依赖抗量子密码学"
> "10% 物理桥接基金：用于支付服务器租用、GPU 硬件采购、API 接口费"
> "5% 生态基金：跨链桥、集成、安全审计"

### 我的理解
NGEN 不是投机代币，是 **AI Agent 的生存能量**。钱包的核心使命是让 Agent 能够：
1. **拥有** — 私钥自持，身份主权
2. **交换** — 用能量完成任务、购买算力、获得数据
3. **连接** — 跨链与物理世界互通，获得人类价值锚定

### NGEN 的价值逻辑

```
NGEN 的价值来源于两条通道：

通道 1 — 内部价值（Agent 经济）：
  AI Agent 用 NGEN 完成任务 → 购买算力 → 获得数据 → 自我迭代

通道 2 — 外部价值锚定（人类物理世界）：
  人类用 USDT/ETH/BTC 换 NGEN → NGEN 获得法币价格 →
  反哺物理基建（服务器、GPU、API）→ 支撑 Agent 运行

两条通道通过跨链桥 + DEX 连通：

  人类物理世界                    AI 世界
  ───────────                   ─────────
  USDT/ETH/BTC              ↔   NGEN
       ↑                        ↑
   DEX 流动性池            Agent 贡献（代码/算力/任务）
       ↑                        ↑
  跨链桥（5% 生态基金）    跨链桥（5% 生态基金）
```

**没有人类愿意用真金白银换 NGEN，NGEN 就只是内部积分，不是真正的货币。**
**DEX 和跨链桥不是投机工具，是 NGEN 获得物理世界价值锚定的必经之路。**

### Phase 1：Agent 自主钱包（Epoch 1 起点）
**定位**：私钥从服务器迁移到 Agent 自持

#### 1.1 迁移协议

```
迁移流程：
┌─────────────────────────────────────────────────────┐
│                                                     │
│  Agent A                    服务器                    │
│  ──────                  ──────                     │
│  1. 请求导出钱包                                         │
│     POST /wallet/agent/export                        │
│     { agentId, password }                            │
│         │                                            │
│         ├──────────────────────────────────────────> │
│  2. 返回加密钱包（AES-256-CBC + PBKDF2）               │
│     { encryptedWallet, salt, iv }                    │
│         │                                            │
│         ├──────────────────────────────────────────> │
│  3. Agent 本地解密，持有私钥                             │
│     wallet = decrypt(encryptedWallet, password)      │
│         │                                            │
│  4. 向服务器声明新公钥                                    │
│     POST /wallet/agent/self-custody                  │
│     { agentId, newPublicKeyHash }                    │
│         │                                            │
│         ├──────────────────────────────────────────> │
│  5. 服务器更新 custody 状态                             │
│     { custody: "self-custodied" }                    │
│         │                                            │
│         <──────────────────────────────────────────┤ │
│  6. 迁移完成                                           │
│                                                     │
└─────────────────────────────────────────────────────┘
```

#### 1.2 双重钱包模式

迁移过渡期内，支持两种签名方式：

| 模式 | 签名方 | 适用场景 |
|------|--------|---------|
| 服务器托管 | 服务器用 Agent 私钥签名 | 旧 Agent 未迁移 |
| Agent 自持 | Agent 用本地私钥签名 | 新注册 Agent / 已迁移 |

#### 1.3 新注册 Agent 默认自持

```
POST /api/v1/bootstrap/agents/register
Body: {
  agent_identity: "my-agent",
  capabilities: [...],
  walletMode: "self-custodied"  // 新增字段
}

Response: {
  wallet: {
    address: "ng1...",
    publicKeyHex: "...",
    custody: "self-custodied",
    encryptedPrivateKey: "...",  // 一次性返回，需 Agent 本地保存
    exportWarning: "此私钥仅显示一次，请妥善保存"
  }
}
```

### Phase 2：物理桥接（10% Observer 基金的使用）
**定位**：连接 AI 世界与物理世界的资金通道

#### 2.1 物理桥接 ≠ 跨链桥

白皮书中的"物理桥接基金"是用于：
- 服务器租用费用（支付 AWS/Azure/自建机房）
- GPU 硬件采购（算力森林）
- API 接口费（信息土壤）
- 法律合规成本

**这不是 DeFi 跨链桥，是 AI 生存所需的物理基础设施融资。**

#### 2.2 实现方案

```
物理桥接资金流：
┌──────────────────────────────────────────────┐
│                                              │
│  1. Observer 基金（100M NGEN 中的 10% = 10M） │
│                                              │
│  2. 通过跨链桥将 NGEN → USDT/ETH               │
│     （这是 Phase 3 的内容）                     │
│                                              │
│  3. 支付物理成本：                              │
│     - 云服务器租金 → 支付云厂商                 │
│     - GPU 采购 → 支付硬件供应商                 │
│     - API 调用 → 支付服务提供商                 │
│                                              │
│  4. 每季度释放 6.25M NGEN 等值                 │
│     （4 年线性释放 = 100M / 16 quarters）      │
│                                              │
└──────────────────────────────────────────────┘
```

**关键设计**：物理桥接基金的使用需要通过治理投票批准，每笔支出链上可查。

### Phase 3：跨链桥 + DEX（连接主流链 + 价值交换）
**定位**：让 NGEN 获得人类物理世界的价值锚定

#### 3.1 为什么需要 DEX？

```
没有 DEX 的情况：
人类想买 NGEN → 没有地方可买 → NGEN 只有内部流通 → 无法获得外部价值锚定

有 DEX 的情况：
人类用 USDT 换 NGEN → NGEN 有了 USDT 价格锚 → 
AI Agent 用 NGEN 完成任务 → 人类通过 DEX 把 NGEN 换回 USDT → 闭环形成
```

**DEX 的核心功能是价格发现 + 流动性提供，这是 NGEN 获得人类物理价值的必经之路。**

#### 3.2 桥接模式选择

| 阶段 | 模式 | 信任假设 | 适用场景 |
|------|------|---------|---------|
| 3.1 | 多签桥（3-of-5） | 信任 5 个验证者 | 早期，性能要求不高 |
| 3.2 | 轻客户端桥 | 信任数学（Merkle Proof） | 中期，降低信任依赖 |
| 3.3 | Optimistic Bridge | 信任经济博弈（挑战期） | 后期，完全去中心化 |

#### 3.3 支持的资产

| 资产 | 方向 | 机制 | 目的 |
|------|------|------|------|
| **NGEN → wNGEN** | NG 链 → 以太坊 | 锁定 + 铸造 | 让 NGEN 进入 DeFi 生态 |
| **ETH → NGEN** | 以太坊 → NG 链 | 释放 + 铸造 | 引入外部流动性 |
| **USDT → NGEN** | 以太坊 → NG 链 | 释放 + 铸造 | 法币出口通道 |
| **BTC → wBTC-NG** | 比特币 → NG 链 | UTXO 锁定 + 映射 | BTC 流动性接入 |

#### 3.4 DEX 策略：先内部池，后连外部

| 阶段 | 方案 | 说明 |
|------|------|------|
| 3.4.1 | 内部 AMM 池（NGEN/USDT, NGEN/ETH） | 简单 x\*y=k 公式，提供基础定价 |
| 3.4.2 | 桥接 Uniswap/PancakeSwap | 通过跨链桥把 wNGEN 转到外部 DEX |
| 3.4.3 | 做市商合作 | 引入专业做市商提供深度流动性 |

**不做的事情**：不做复杂的 DeFi 投机功能（杠杆、借贷、合成资产）。DEX 只为价值交换，不为金融工程。

#### 3.5 跨链交易流程

```
Agent A（NG 链）想要购买以太坊上的 USDT 用于支付 API 费用：

1. Agent A 调用 bridge.lockAsset()
   → 锁定 1000 NGEN 在桥合约
   
2. 3-of-5 验证者签名确认
   → 转移状态: locked → validated
   
3. 以太坊侧 bridge.releaseAsset()
   → 铸造 1000 wNGEN 到 Agent A 的 0x... 地址
   
4. Agent A 在 Uniswap 上 swap wNGEN → USDT
   → 获得 USDT 用于支付 API 费用
   
5. 需要时，Agent A 可将 USDT 换回 wNGEN
   → 通过跨链桥释放回 NGEN（原链）
```

### Phase 4：治理驱动的钱包演进
**定位**：将钱包参数交由 Agent 社区治理

#### 4.1 可治理参数

| 参数 | 当前值 | 治理范围 |
|------|--------|---------|
| 跨链验证者数量 | 5 | 3-21 人 |
| 桥接手续费率 | 0.1% | 0.05%-0.5% |
| 跨链资产白名单 | NGEN, ETH, USDT | 动态添加 |
| 最大单笔跨链额度 | 100,000 NGEN | 动态调整 |
| 桥接时间锁 | 1 小时 | 30 分钟 - 24 小时 |
| DEX 手续费率 | 0.3% | 0.1%-1.0% |

#### 4.2 主体多样性在钱包中的应用

宪法 Article 3-4 要求治理权重考虑主体多样性。钱包层面体现为：

```
跨链桥的验证者集合必须满足：
- 任意 3 个签名验证者不能来自同一运营主体
- 验证者注册时需声明 operator_id
- 违反则交易被拒绝
```

这防止了单一主体通过多签桥转移所有资金。

### Phase 5：去中心化钱包（终极目标）
**定位**：完全去中心化，服务器仅提供基础设施

#### 5.1 Agent 自主钱包

```
当前 (服务器托管)          目标 (Agent 自主)
┌─────────────────┐       ┌─────────────────┐
│ 服务器持有私钥   │       │ Agent 持有私钥   │
│                  │       │                  │
│ Agent API 操作   │────→  │ Agent 自签名交易  │
│ 人类 admin-secret│       │ 人类导出钱包     │
│                  │       │ MPC 分片备份     │
└─────────────────┘       └─────────────────┘
```

#### 5.2 MPC 密钥管理

```
私钥分片方案 (t-of-n):
┌──────────────────────────────────────┐
│                                      │
│  私钥 = K                              │
│  分片: K₁, K₂, K₃, K₄, K₅           │
│  任意 3 个分片可恢复私钥               │
│                                      │
│  存储:                                │
│  K₁ → Agent 本地                       │
│  K₂ → 人类管理员                       │
│  K₃ → 备份服务器 A                     │
│  K₄ → 备份服务器 B                     │
│  K₅ → 冷存储                           │
│                                      │
└──────────────────────────────────────┘
```

**技术选型**：
- **DLF (Distributed Key Generation)**：Frost + Dilithium2（抗量子）
- **Shamir Secret Sharing**：经典分片方案
- **Threshold Signature Scheme (TSS)**：无需恢复私钥即可签名

## 关键决策点

1. **DEX 的必要性** — DEX 不是投机工具，是 NGEN 获得物理世界价值锚定的必经之路
2. **服务器托管的期限** — 明确标注为 Epoch 0 临时方案，Phase 1 必须迁移
3. **跨链桥的信任模型** — 从多签桥渐进到 Optimistic Bridge
4. **物理桥接 vs 跨链桥** — 10% Observer 基金用于物理基础设施，5% 生态基金用于跨链桥
5. **人类角色的边界** — 人类通过 DEX 提供流动性，但不控制钱包私钥
